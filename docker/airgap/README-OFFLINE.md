# wg-panel — بسته‌ی نصبِ آفلاین (Docker)

این بسته برای اوبونتوی ۲۲.۰۴/۲۴.۰۴ **بدونِ اینترنت** است و خودکفاست:
ایمیجِ آماده‌ی Docker + مخزنِ آفلاینِ خودِ docker + نصابِ یک‌دستوری.
پنل، WireGuard، fail2ban و پروکسی همه داخلِ همان یک کانتینرند.

## محتوا

| فایل | چیست |
|---|---|
| `wg-panel-image-*.tar.gz` | ایمیجِ Docker (با `docker load` وارد می‌شود) |
| `apt/` | مخزنِ آفلاین: `docker.io` + `docker-compose-v2` و همه‌ی وابستگی‌ها |
| `docker-compose.yml` | نسخه‌ی آفلاین — ایمیجِ پین‌شده، بدونِ build |
| `.env.example` | پیکربندی (کپی به `.env`) |
| `install.sh` | نصابِ idempotent — همه‌ی گام‌ها |
| `verify-checksums.sh` + `manifests/` | سنجشِ یکپارچگیِ بسته |
| `VERSION` / `ARCH` | نسخه‌ی پنل (۱۲ رقمِ هش) و معماریِ هدف |

## نصب

بسته را به مسیری **بدونِ فاصله** ببرید (مثلاً `/opt/`)، باز کنید و:

```bash
sudo bash install.sh --server-host <IP-یا-دامنه‌ی-عمومی> --up
```

همین. نصاب اول یکپارچگی و معماری را می‌سنجد، بعد اگر docker نبود از `apt/`
همین بسته نصبش می‌کند، ماژولِ wireguard را ماندگار می‌کند، ایمیج را load
می‌کند و پنل را بالا می‌آورد.

پنل: `https://SERVER:8787` — گواهی self-signed است (اخطارِ مرورگر را
بپذیرید). نامِ کاربری `admin` و **اولین رمزی که وارد کنید ثبت می‌شود؛
بلافاصله بعدِ نصب وارد شوید.**

بدونِ `--up`: نصاب فقط آماده می‌کند و می‌ایستد تا `.env` را ویرایش کنید؛
بعد خودتان `docker compose up -d` بزنید.

## داده و بکاپ

همه‌چیز در `data/` کنارِ همین فایل‌هاست: `data/panel/` (کاربران/دیتابیس/TLS)،
`data/wireguard/` (کلیدها)، `data/backups/` (آرشیوهای بکاپ).

**بکاپِ خودکار روشن است.** کانتینر systemd ندارد، پس یک زمان‌بندِ کوچک داخلش
هر شب ساعتِ `WG_BACKUP_AT` (پیش‌فرض `04:30` طبقِ `TZ` در `.env`) همان کاری را
می‌کند که دکمه‌ی «پشتیبان‌گیریِ دستی» پنل می‌کند. ۱۴ نسخه نگه می‌مانَد. یک بکاپ
هم ~۱۰ دقیقه پس از نخستین بوت گرفته می‌شود تا نصب یک شبانه‌روز بی‌تورِ ایمنی
نماند؛ اگر سرور سرِ ساعتِ مقرر خاموش بود، اجرای از دست رفته پس از بالا آمدن
جبران می‌شود. صفحه‌ی «پشتیبان‌گیری» پنل «آخرین اجرا / نتیجه / اجرای بعدی» را
نشان می‌دهد. خاموش‌کردن: `WG_BACKUP_ENABLED=false` (دکمه‌ی دستی سرِ جایش
می‌مانَد).

بکاپِ سرد: توقف، آرشیوِ `data/`، شروع:

```bash
docker compose down && tar -czf wg-panel-data-$(date +%Y%m%d).tar.gz data/ && docker compose up -d
```

بازیابی روی ماشینِ نو: همین بسته + پوشه‌ی `data/` قبلی ⇒ `install.sh` و تمام.

## ارتقا

بسته‌ی جدید (با `VERSION` تازه) را باز کنید، `data/` و `.env` قبلی را کنارش
بگذارید (یا در همان مسیر باز کنید) و دوباره `sudo bash install.sh --up` —
داده هرگز بازنویسی نمی‌شود؛ فقط ایمیجِ تازه load و جایگزین می‌شود.

## سه چیز که آگاهانه در ایمیج نیستند

هیچ‌کدام خرابی نیست و هیچ‌کدام به سرویسِ VPN، کاربران، سهمیه و پروکسی کاری
ندارد — فقط آن ردیف/صفحه خالی می‌مانَد:

- **تستِ سرعت** — به CLI ِ رسمیِ Ookla نیاز دارد که در مخزنِ اوبونتو نیست. اگر
  باینری‌اش را دارید، در `docker-compose.yml` از کامنت درآورید:
  `- ./bin/speedtest:/usr/local/bin/speedtest:ro`
- **بکاپِ کاملِ سرور** — آن اسکریپت یک میزبانِ کامل را می‌گیرد (`/etc`،
  گواهی‌ها، یونیت‌ها)؛ کانتینر چنین میزبانی نیست. بکاپِ خودِ پنل (بالا) اجرا
  می‌شود.
- **راستی‌آزماییِ بکاپ** — نسخه‌ی موجود فقط بکاپِ روی فضای ابری را می‌سنجد و
  قاعده‌ی «هیچ بکاپی روی سرور نماند» را اعمال می‌کند؛ عکسِ طرحِ این نصب که
  بکاپ را عمداً در `data/backups/` نگه می‌دارد.

## نکته‌های امنیتی

- **ufw پورت‌های publish شده‌ی docker را فیلتر نمی‌کند.** محدودسازیِ پنل با
  `WG_PANEL_ALLOW_IPS` در `.env` (فیلترِ خودِ پنل) یا بستنِ پورتِ پنل به
  `127.0.0.1` در `docker-compose.yml`.
- `fail2ban` داخلِ کانتینر فعال است: ۵ ورودِ ناموفق در ۱۰ دقیقه ⇒ بنِ ۱ ساعته.
- `data/` و `.env` فقط برای root بمانند (`chmod 700 data`).

## عیب‌یابی

```bash
docker compose logs -f
```

```bash
docker compose exec wg-panel wg show
```

- «ساختِ اینترفیسِ آزمایشیِ wireguard شکست خورد» ⇒ `sudo modprobe wireguard`
  و بعد `docker compose restart`.
- healthcheck ِ `unhealthy` ⇒ یا پنل جواب نمی‌دهد یا اینترفیسِ کاربران پایین
  است: `docker inspect --format '{{json .State.Health}}' wg-panel`
- نصابِ apt شکست خورد ⇒ خروجیِ `verify-checksums.sh` را ببینید؛ بسته باید
  با معماریِ همین میزبان ساخته شده باشد (`cat ARCH`).
