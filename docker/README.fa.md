# نصبِ wg-panel با Docker Compose روی یک سرورِ تازه‌ی اوبونتو

> English: [README.md](README.md)

پنل + WireGuard داخلِ **یک کانتینر**، با همان رفتارِ نصبِ ansible: نخستین اجرا
`config.json` و کلیدها و گواهیِ TLS را می‌سازد، اجراهای بعدی فقط کدِ پنل را از
ایمیج تازه می‌کنند و به داده دست نمی‌زنند. رمزِ مدیر در **نخستین ورود** به پنل
ثبت می‌شود.

> ⚠️ این مسیر برای یک سرورِ «تازه» است. استقرارِ خودِ نگه‌دارنده‌ی پروژه پنل را
> بدونِ Docker و با systemd اجرا می‌کند و مسیرِ نصبش جداست.

## پیش‌نیازها

- اوبونتوی ۲۲.۰۴ یا ۲۴.۰۴ (x86_64 یا arm64) با دسترسیِ root
- کلِ این مخزن روی سرور باشد (با `git clone`، یا `rsync`/`scp` از ماشینی
  دیگر)
- بیلد به اینترنت نیاز دارد (apt داخلِ ایمیج) — برای ماشینِ **بدونِ اینترنت**
  بسته‌ی آفلاینِ همین نسخه را روی یک ماشینِ متصل به اینترنت بسازید و ببرید:
  [docker/airgap/README.md](airgap/README.md) (ایمیجِ آماده + مخزنِ آفلاینِ
  خودِ docker + نصابِ یک‌دستوری)

## نصب — چهار قدم

```bash
sudo bash host-setup.sh
```

```bash
(umask 077 && cp .env.example .env)
chmod 600 .env
```

> `.env` توکنِ رباتِ تلگرام و بقیه‌ی رازهای استقرار را می‌گیرد. `cp` ِ ساده
> مود را از umask می‌گیرد (معمولاً ۰۶۴۴) و روی هاستی که کاربرِ دومی دارد
> خواندنی می‌ماند. نصابِ airgap همین کار را می‌کند؛ مسیرِ دستی هم باید
> با آن بخواند.

سپس `.env` را باز کنید و دست‌کم `WG_SERVER_HOST` (IP یا دامنه‌ی عمومیِ سرور)
را پر کنید — این مقدار در `Endpoint` کانفیگِ کلاینت‌ها می‌نشیند.

```bash
docker compose up -d --build
```

```bash
docker compose logs -f
```

پنل روی `https://SERVER:8787` بالا می‌آید (گواهی self-signed است؛ اخطارِ
مرورگر را بپذیرید). نامِ کاربری `admin` و **اولین رمزی که وارد کنید ثبت
می‌شود** — پس بلافاصله بعدِ نصب وارد شوید، پیش از آنکه کسِ دیگری به این پورت برسد.

## چه چیزی کجا می‌ماند (بکاپ = همین پوشه)

| مسیرِ میزبان | محتوا |
|---|---|
| `data/panel/` | `config.json` (کاربران/secret)، `traffic.db`، کانفیگِ کلاینت‌ها، TLS، `actions.log` |
| `data/wireguard/` | کانفیگ و کلیدهای اینترفیس(ها) + بکاپِ خودکارِ پیش از هر تغییر |
| `data/backups/` | آرشیوهای شبانه و خروجیِ دکمه‌ی «پشتیبان‌گیریِ دستی» (`wg-panel-backup.sh`) — ۱۴ نسخه |

بکاپِ سردِ کامل (پنل خاموش):

```bash
docker compose down && tar -czf wg-panel-data-$(date +%Y%m%d).tar.gz data/ && docker compose up -d
```

بکاپِ گرم بدونِ قطعی: از دکمه‌ی «پشتیبان‌گیریِ دستی» خودِ پنل استفاده کنید —
اسنپ‌شاتِ سازگارِ sqlite می‌گیرد و در `data/backups/` می‌گذارد.

بازیابی روی ماشینِ نو: مخزن + پوشه‌ی `data/` را بگذارید و `up -d --build` —
همین. (تا `data/` هست، هیچ بوت‌استرپی دوباره اجرا نمی‌شود.)

## ارتقا

کدِ جدید را روی سرور بیاورید (`git pull`، یا `rsync`)، بعد:

```bash
docker compose up -d --build
```

entrypoint در هر بوت `wg_panel.py` داخلِ والیوم را با نسخه‌ی ایمیج جایگزین
می‌کند (داده دست‌نخورده می‌ماند). شناسه‌ی نسخه همان قراردادِ مخزن است:
۱۲ رقمِ اولِ SHA-256 ِ `wg_panel.py` — با `cat data/panel/VERSION` ببینید.

## نکته‌های امنیتی که نباید نادیده بگیرید

- **ufw پورت‌های publish شده‌ی docker را فیلتر نمی‌کند.** محدودکردنِ پنل را با
  `WG_PANEL_ALLOW_IPS` در `.env` انجام دهید (فیلترِ خودِ پنل، مستقل از
  فایروال)، یا در `docker-compose.yml` پورتِ پنل را به `127.0.0.1` بچسبانید و
  از راهِ تونل/SSH واردش شوید.
- `fail2ban` داخلِ کانتینر فعال است (پیش‌فرض): ۵ ورودِ ناموفق در ۱۰ دقیقه ⇒
  بنِ ۱ ساعته‌ی همان IP فقط روی پورتِ پنل.
- `data/` را فقط برای root نگه دارید: `sudo chmod 700 data` — `config.json`
  ِ secret و کلیدهای خصوصی همان‌جاست.
- کانتینر فقط `NET_ADMIN` دارد، نه `privileged`؛ ماژولِ wireguard را
  `host-setup.sh` روی میزبان لود و ماندگار می‌کند.

## تفاوت‌ها با نصبِ systemd (صادقانه)

| قابلیت | وضعیت در Docker |
|---|---|
| پنل، کاربرها، سهمیه/انقضا، QR، ربات و هشدارِ تلگرام | ✅ کامل |
| روشن/خاموشِ تونل‌ها از پنل | ✅ از راهِ شیمِ `systemctl` → ‏`wg-quick` |
| پروکسیِ squid | ✅ داخلِ همان کانتینر (پورت 18080) |
| دکمه‌ی «پشتیبان‌گیریِ دستی» | ✅ اجرای همان اسکریپتِ بکاپِ نقش |
| بکاپِ «شبانه‌ی» خودکار | ✅ زمان‌بندی داخلِ کانتینر جانشینِ تایمرِ systemd است — `WG_BACKUP_AT`، پیش‌فرض ۰۴:۳۰ |
| آپلودِ ابریِ بکاپ (MEGA S4) | ⚙️ اختیاری — دو فایلِ secrets را mount کنید (کامنت‌های compose)؛ تا آن‌وقت بی‌صدا رد می‌شود |
| راستی‌آزماییِ بکاپ | ❌ نسخه‌ی موجود فقط MEGA-محور است و قاعده‌ی «هیچ بکاپی روی سرور نماند» را اعمال می‌کند — عکسِ طرحِ این نصب |
| ردیفِ «بکاپِ کاملِ سرور» | ❌ آن اسکریپت یک میزبانِ کامل را می‌گیرد (`/etc`، letsencrypt، یونیت‌ها)؛ کانتینر چنین میزبانی نیست |
| صفحه‌ی تستِ سرعت | ⚙️ به CLI ِ Ookla نیاز دارد که در مخزنِ اوبونتو نیست — باینری را خودتان mount کنید (کامنت‌های compose) |
| AmneziaWG (تونل‌های awg) | ⚙️ فقط اگر باینری‌ها را خودتان mount کنید — در مخزن و apt نیستند |
| زنجیره‌ی WARP/SNI، ECMP، نگهبان‌های تونل | ❌ خاصِ یک توپولوژیِ چندتونلیِ مشخص — خارج از دامنه‌ی این نسخه |

هر ❌ بالا صفحه/ردیفی است که **خالی** می‌مانَد، نه خراب؛ و هیچ‌کدام به سرویسِ
VPN، کاربران، سهمیه و پروکسی کاری ندارد.

### زمان‌بندِ بکاپ

کانتینر systemd ندارد و خودِ `wg_panel.py` هم بکاپ را زمان‌بندی نمی‌کند —
فقط وضعیتِ یونیت‌ها را می‌خواند و با دکمه راه می‌اندازد. پس یک زمان‌بندِ کوچک
(`wg-panel-cron`) کنارِ پنل اجرا می‌شود و **همان** jobی را می‌زند که دکمه
می‌زند؛ در نتیجه ستون‌های «آخرین اجرا / نتیجه / اجرای بعدی» صفحه‌ی بکاپ
همان‌قدر راست می‌گویند که روی نصبِ systemd.

- هر شب ساعتِ `WG_BACKUP_AT` (پیش‌فرض `04:30` طبقِ `TZ`)؛ ۱۴ نسخه نگه می‌ماند
- نصبِ تازه یک بکاپ هم ~۱۰ دقیقه پس از نخستین بوت می‌گیرد تا هیچ نصبی یک
  شبانه‌روز بی‌تورِ ایمنی نماند
- اگر کانتینر سرِ ساعتِ مقرر خواب بود، اجرای از دست رفته کمی بعد از بالا
  آمدن جبران می‌شود (همان رفتارِ `Persistent=true` در systemd)
- با `WG_BACKUP_ENABLED=false` خاموش می‌شود؛ دکمه‌ی دستی سرِ جایش می‌مانَد
- state در `data/panel/units/` است، پس «آخرین اجرا» از
  `docker compose down && up` رد می‌شود

## عیب‌یابی

```bash
docker compose logs -f wg-panel
```

```bash
docker compose exec wg-panel wg show
```

```bash
docker compose exec wg-panel tail -50 /var/log/wg-panel/systemctl-shim.log
```

- «ساختِ اینترفیسِ آزمایشیِ wireguard شکست خورد» در لاگ ⇒ روی میزبان
  `sudo modprobe wireguard` (یا `host-setup.sh`) و بعد
  `docker compose restart`.
- کلاینت وصل می‌شود ولی اینترنت ندارد ⇒ داخلِ کانتینر
  `sysctl net.ipv4.ip_forward` باید `1` باشد و
  `iptables -t nat -S POSTROUTING` قاعده‌ی MASQUERADE را نشان بدهد؛ هر دو را
  entrypoint می‌سازد و اگر compose را دست‌کاری نکرده باشید برقرارند.
- healthcheck ِ `unhealthy` یعنی یا پنل جواب نمی‌دهد یا اینترفیسِ اصلیِ
  کاربران پایین است — `docker inspect --format '{{json .State.Health}}' wg-panel`
